# 复盘：32 小时搭起来，跑了 405 篇，学到了什么

从第一行代码到上线，大约 32 小时。最后 92 个人交了 405 篇，全部评完。

这份文档记的不是功能清单，是**真正学到的东西**。

---

## 一、数据说了什么

### 最有说服力的一个数字

> **投过两次以上的 69 个人里，50 个人（72%）分数涨了。**
> 平均涨 7.9 分，最多的涨了 37 分。第一次投平均 72.0 分，改到最好那次平均 79.8 分。

这条比「上线了」「没崩」都重要。这场比赛的设计目标不是选出好文章，
是**让人反复改**。72% 说明这个循环真的转起来了：学生拿到评语，回去改，再投，分数真的往上走。

### 被打回去之后没走

有 117 次，学生改完一稿反而比上一稿分低。其中 97 次，他又投了一稿。
分数掉下来很难受，82% 的人选择了继续改。

### 学生写给 AI 的话，比写给读者的还多

截至 09-06（当时 389 篇），正文共 35.1 万字，创作过程记录 104.4 万字，差不多是正文的 3 倍。
写得最多的一个人，光过程记录就写了 4.2 万字，相当于一部中篇小说，
全部是「我怎么让 AI 写出我想要的东西」。这比任何总结都更能说明这场比赛在比什么。

### 学生在哪一维吃亏

| 维度 | 得分率 | 改稿后涨 |
|---|---|---|
| 语言辨识度 | **63.7%** | +1.7 |
| 结构完成度 | 67.4% | +1.6 |
| 反套路 | 68.9% | +1.2 |
| 真实感 | 76.6% | +0.9 |
| 人的驱动 | 82.5% | **+2.5** |

**「语言辨识度」最难拿分**，这正是 AI 写作的通病：通顺、正确、挑不出错，但没有个人腔调，读完不知道是谁写的。
改稿后涨得最多的恰好是它和「人的驱动」，说明评语指到了痛处，不是靠堆字数刷分。

### 题目的形状决定答案的形状

同一批人，问「你眼中的大学」，写出来的多是落差；问「你做成了什么」，写出来的是气性。
测到的不完全是这代人的底色，也是题目的形状。**出题的人要为答案负一部分责任。**

这也是为什么三个赛道都是**具体题目**（我和 AI / 我眼中的大学 / We Young, We Create），
而不是抽象的大词。参赛的多是刚上大学的学生，具体的题目才写得出具体的事。

## 二、踩过的坑，按类型分

两天里修了近 20 个真 bug。归一下类，会发现它们不是随机分布的。

### 类型一：静态检查看不见的（最贵的一类）

| 坑 | 为什么查不出来 |
|---|---|
| 赛道下拉框一直是空的，人工投稿根本选不了题 | 所有自动化测试都走 API，不经过页面 |
| 长文章底部被吸底页脚盖住，滚不到底 | HTML 和 CSS 各自都对，是两条正确规则叠在一起出的事 |
| 重复的 HTML id，内容写进了错的容器 | 浏览器控制台零报错 |

**教训：** 凡是人要用眼睛看、用手点的东西，就必须真的看一眼。
补的办法是无头浏览器截图，再把页面里的函数原样取出来单独跑。

### 类型二：自己误诊（第二贵）

- Python 默认的 User-Agent 被中转站 403 拦掉。先诊断成「间歇性故障」，再诊断成「限流」，
  还为此写了一套退避重试，**全是错的**。加一个正经 UA，立刻全通
- 网络断开的异常（RemoteDisconnected）不属于 URLError，漏掉它，一次网络抖动就让学生白丢一次机会

**教训：** curl 通、浏览器通、只有代码不通，先怀疑请求头，别怀疑对方挂了。

### 类型三：配置和部署

- 同步脚本带了「删除多余文件」，把服务器上的密钥文件删光，重启后所有模型 401
- 往配置文件追加一行，上一行没有换行符，两行黏成一行，新 key 静默失效
- 没关输出缓冲，服务日志里什么都看不到

**教训：** 部署脚本必须部署完自己验一遍：key 还在吗、服务活着吗、数据还是那么多吗。

### 类型四：把业务规则和防攻击混在一起

按 IP 限流，结果挡死了整栋宿舍楼，**栽了两次**。校园网整栋楼共用一个出口 IP。

**教训：** 「每人每小时 3 次」是业务规则，认的是人；「每个 IP 每秒 30 次」是防打爆，认的是机器。
两者不能用同一套计数。

### 类型五：模型这一层

- 推理模型把 `max_tokens` 全花在思考上，正文返回空
- 换模型只换了供应商没换模型名，把 A 家的模型名发给 B 家，直接 400
- 写进 prompt 的硬约束没用：写了「每人最多两个奖」，模型照样发三个
- 中转站会悄悄加隐藏前缀。实测发一句「1+1=?」，不同供应商的输入开销从 10 token 到 5700 多 token，**差 500 倍**

## 三、事后看，哪些决定是对的

1. **内规和外规分家。** 判据从不对外，对外只有一个出口，自检里有自动泄露检查，比赛中抓到过 4 处漏网。
   学生只知道题目和五个维度，要自己找怎么写好，而不是照着刷
2. **能算的规则用代码兜。** 模型忘了好几次之后才学乖：能用 if 判断的，就别指望模型记住
3. **榜单和阅览室走实时接口，页面只是壳子。** 一开始把数据烘进页面，评完分不重新生成就一直显示「还没有作品」
4. **轮换加熔断，不用随机。** 随机会让某一家连续被抽中，轮转才是真均摊
5. **两段式评分。** 快评几秒给档位，详评几十秒给分数和评语。学生等待的那几十秒里先有东西看
6. **分数收紧。** 一开始随手就打 80 多分。分数给满了，学生就没有再改一次的动力。收紧之后才有 72% 的提升率

## 四、该早点做的

1. **用量记账第一天就加。** 评完一百多篇才想起来 API 返回里有用量，那一批永远只有估算
2. **前端一开始就要截图验证。** 下拉框空了 10 个版本没人发现，因为测试全走 API
3. **先量评分波动，再定赛制。** 同一篇重打会差 ±13 分，这是做到一半才实测出来的。早知道的话，决赛圈的机制会设计得更早
